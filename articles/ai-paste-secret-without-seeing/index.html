讓 AI 幫我設定 API key，可以不讓它看到嗎？｜剪貼簿直接交給程式，AI 只看到「完成」

密鑰要放進 Cloudflare 這類雲端服務時，交給 AI 做最省事，但 AI 一碰到值，值就進了對話紀錄。這篇介紹一支免費的 Mac 小工具：值從剪貼簿直接交給程式，AI 只負責下指令，看到的只有「完成」那一行。文末可下載。

做網站接 Google 登入、讓官網的 AI 客服呼叫模型，都會碰到同一個步驟：把一把密鑰放進雲端服務的「秘密設定」。這件事交給 AI 做最省事，但 AI 一碰到值，值就進了對話紀錄。我做了一支小工具，讓 AI 按網頁的複製鍵、跑一行指令，密鑰從剪貼簿直接交給 Cloudflare 的命令列工具，AI 從頭到尾只看到「完成」那一行。這篇講它怎麼做到、限制在哪裡，文末可以下載。

適合誰
  • 用 AI 幫忙架網站、接登入、串 API，卡在「密鑰要放到哪裡、怎麼放」的人
  • 知道 API key 不該貼給 AI，但不知道要把 key 送進雲端時怎麼辦的人
  • 幫客戶設定 AI 工具，要交代密鑰流程的顧問與接案者

工具目前只支援 Mac。用 Windows 的話，前三節的想法一樣適用，工具本身不能跑。

一、為什麼要讓 AI 代貼，又不能讓它看到

雲端服務上的程式要用密鑰時，密鑰不能寫在程式碼裡，要另外放進服務的「秘密設定」。以 Cloudflare（很多人拿來放網站的平台）為例，要用它的命令列工具 wrangler，在終端機跑 wrangler pages secret put 名稱，再把值貼進去。

這篇會一直出現兩個詞，先講白話：「CLI」是在終端機裡打字操作的工具，wrangler 就是 Cloudflare 的 CLI；「stdin（標準輸入）」是程式之間私下遞東西的管道，值從這裡遞過去，不會寫在畫面上的指令裡。

步驟不難，難在要記指令、開對資料夾、選對帳戶。所以很多人會交給 AI：「幫我把 Google 登入的密鑰設定好」。這時 AI 最直覺的做法是請你把值貼進對話，或自己去網頁讀出來再填。兩種做法，值都會留在對話紀錄裡。

上一篇〈API key 可以貼給 AI 嗎？〉講過，在你自己電腦上跑的程式，可以把 key 存進 Mac 鑰匙圈，讓程式自己去拿。但這次 key 的目的地是雲端，鑰匙圈幫不上忙：總要有人把值交給 wrangler。

一顆比較隱形的雷我在設定 Google 登入時，讓 AI 用瀏覽器幫我找 Google Cloud 主控台的「複製」按鈕。那顆按鈕有一段給視障者螢幕閱讀器念的隱藏文字（aria-label），畫面上看不到，但程式讀得到，裡面直接寫著完整的用戶端密鑰。AI 只是列出頁面上有哪些按鈕，密鑰就跟著進了對話紀錄。我只能回 Google Cloud 把那把停用、刪掉，再發一把新的。

所以需求很明確：AI 要能替我完成設定，但值一個字都不能經過它。

先把 key 放對地方
  • API key 可以貼給 AI 嗎？｜存進 Mac 鑰匙圈，讓程式自己去拿：這一段講 key 要送上雲端，那篇講 key 留在自己電腦上時怎麼存、外洩了怎麼止血

二、AI 怎麼做到看不到值：五個步驟

secret-paste 是一支 Python 小程式。AI 只負責按複製鍵和下指令，值的處理全在程式裡。

步驟做什麼為什麼這樣做
1. 從剪貼簿拿值你或 AI 按網頁上的「複製」鍵，值進剪貼簿；程式自己讀剪貼簿AI 不用讀網頁上的字，也不用你貼進對話
2. 只驗開頭檢查開頭對不對（例如 Google OAuth 密鑰是 GOCSPX-）、長度夠不夠、中間有沒有空白換行；不合就停剪貼簿裡可能是別的東西，貼錯會把錯的值寫上雲端
3. 從 stdin 交給 CLI值從「標準輸入」交給 wrangler，不放進指令本身放在指令裡的字，會出現在系統的行程列表和終端機歷史紀錄
4. 輸出含值先遮wrangler 回的訊息裡，只要出現值本身或值裡任何連續 6 個字元，都換成 [已遮蔽]；自訂指令的輸出完全不轉述有些工具出錯時會把值的前幾碼印出來
5. 一律清剪貼簿成功、失敗、參數打錯、被中斷，最後都清空剪貼簿參數打錯時，剪貼簿裡多半正放著密鑰

AI 最後看到的只有一行，就是上面總結圖裡那行「完成」。失敗也只有一行，例如「失敗：剪貼簿開頭不符（預期 GOCSPX-），未寫入」。AI 照實轉告你就好。

網頁沒有複製鍵、值在你手上時，把指令裡的 --source clipboard 改成 --source dialog，程式就會跳出 macOS 的隱藏輸入框，你自己貼進去，畫面上只有圓點。

同一個想法用在個資上
  • 可以讓 AI 大量處理個資，又不讓它讀到內容嗎？：這一段讓 AI 只下指令、值交給程式搬；那篇用同一個分工處理個資，AI 只看欄位名稱

三、按複製鍵那一步，要先交代 AI

這套流程裡最容易出事的地方，在程式跑之前：AI 用瀏覽器找複製鍵的那一下。

像 Google Cloud 那樣把密鑰寫進按鈕隱藏文字的網站，只要 AI 回傳按鈕的文字，值就漏了。所以交代 AI 時要寫明：找按鈕只回傳「找到沒有」和位置，不回傳按鈕的文字或 aria-label。真的要回傳文字，先在網頁裡把像密鑰的字串遮掉再回傳。

其他服務的複製鍵有沒有同樣問題，我沒有逐一測過。碰到新網站，一律先當作會漏。

最簡單的做法：複製鍵你自己按AI 不一定要操作瀏覽器。你自己在網頁上按「複製」，再跟 AI 說「已經複製好了，跑 secret-paste」，AI 只負責下指令。這樣不需要任何瀏覽器自動化工具，也完全碰不到上面那顆雷。讓 AI 按複製鍵，是在你不想自己找按鈕、而且它已經接好瀏覽器工具時才用。

四、怎麼用：前提、下載、貼給 AI 的交代

前提

需要怎麼確認
macOS程式用到 Mac 內建的剪貼簿指令與對話框，Windows、Linux 不能用
Python 3.8 以上終端機打 python3 --version

這些都可以請你的 AI 幫你確認、幫你裝。裝東西不會碰到密鑰。

下載

壓縮檔解開後有 secret-paste.py（程式）與 README.md（每個參數的說明和完整範例）兩個檔案，放在任何資料夾都可以。下面的例子假設你放在個人資料夾裡的 tools/secret-paste/，放別的地方，指令裡的路徑就跟著換。授權是 MIT，可以自由使用、修改、分享，不提供任何擔保。

下載 secret-paste.zip 先看程式碼 先看說明

程式碼不長，下載前可以先請你的 AI 讀一遍，確認它真的只做這篇講的事。這支也收在小工具頁的免費下載區。

可以直接貼給 AI 的交代

接下來要把 <密鑰名稱> 設定到 <Cloudflare Pages 專案名／Worker 名稱>。 請用 secret-paste.py 處理，規則： 1. 不准讀出、印出、轉述密鑰的值；不准跑 pbpaste。 2. 複製鍵我自己按。你如果要用瀏覽器幫我按，找按鈕只回傳座標或布林值，不回傳按鈕的文字或 aria-label。 3. 先跑 --dry-run 確認會寫到哪裡，給我看那一行。dry-run 跑完會清空剪貼簿，我說可以之後，我再按一次複製鍵，你正式跑。 4. wrangler 如果裝在專案裡，指令要加 --wrangler 指到 node_modules/.bin/wrangler。 5. 工具只會回一行「完成」或「失敗」，照實轉告我就好。

AI 實際會跑的指令長這樣（Cloudflare Pages）：

python3 ~/tools/secret-paste/secret-paste.py \ --target pages --key GOOGLE_CLIENT_SECRET --preset google-oauth \ --project <Pages 專案名> --account <Cloudflare 帳戶 ID> --source clipboard

wrangler 如果是照官方建議裝在專案裡，指令要多加 --wrangler "$PWD/node_modules/.bin/wrangler"，不然程式會說找不到 wrangler。

也可以寫進 Cloudflare Worker（--target worker --name <Worker 名稱>），或交給其他會從標準輸入讀值的工具，例如 GitHub 的 gh secret set（--target cmd -- gh secret set 名稱）。

--account 一定要帶同一個登入可能管好幾個 Cloudflare 帳戶。不帶的話，非互動模式可能失敗，或寫到別的帳戶去，所以程式沒拿到帳戶 ID 就不跑。
交給 AI 做設定，還有哪些要本人來
  • 換電腦，設定又要重來一次嗎？：這一段只講密鑰這一步，那篇講把整套設定交給 AI 時，哪些授權步驟一定要你本人按

五、限制：它防得住什麼、防不住什麼

  • 防的是 AI 不小心看到，防不了存心偷看的程式。一個能在你電腦上跑指令的 AI，真的想看，自己跑剪貼簿讀取指令就拿得到。這支工具讓「正常做事」的路徑不經過值，擋不住故意繞路。所以交代裡那句「不准跑 pbpaste」要留著。
  • 剪貼簿歷史工具清不到。Maccy、Raycast、Paste 這類工具會另外留一份紀錄，這支只清空目前的剪貼簿。有裝的話，在那個工具裡把來源排除，或改用隱藏輸入框。
  • 它只管自己。AI 在它之前用瀏覽器讀頁面、或之後另外讀剪貼簿，它管不到。第三節那顆雷要靠交代防。
  • 隱藏輸入框還沒實際跳框測過，目前只驗過程式語法。
  • 只用假值測過。我用假的剪貼簿、假的 wrangler 測了 15 種情況（格式不符、值被印回來、參數打錯、被中斷等），全部符合預期，每次跑完剪貼簿都是空的；但沒有對真的 Cloudflare 專案寫入過。Cloudflare 官方文件寫明 Worker 用的 wrangler secret put 可以接管線輸入，Pages 用的 wrangler pages secret put 文件沒寫到這點，所以第一次用請先拿不重要的測試值試：名稱取 SECRET_PASTE_TEST、值隨便打一串符合開頭的字，寫進去看到「完成」、到 Cloudflare 後台確認有這個名稱，再把它刪掉。
  • 遮蔽只認得原樣。如果某個工具把值改寫成別的格式再印出來，遮不到。所以自訂指令的輸出一律不轉述。

六、鑰匙圈和 secret-paste，什麼時候用哪個

你的情況用哪個
程式在你自己電腦上跑，要用 keyMac 鑰匙圈，做法見〈API key 可以貼給 AI 嗎？〉
key 要放進雲端服務（Cloudflare、GitHub Actions），想讓 AI 幫你設定secret-paste
key 要放進雲端服務，你自己會開終端機自己跑 wrangler pages secret put 名稱，照提示貼上，最直接；secret-paste 是給「想交給 AI 做」的時候用
key 已經貼給過 AI，或在對話紀錄裡出現過先到後台停用那把、產一把新的，再用上面兩種方式之一放好

給你的 AI 讀的技術備忘（人可以跳過）

  • 值的來源：pbpaste（剪貼簿）或 osascript 的 display dialog ... with hidden answer；--source clipboard 時不跳框
  • 格式檢查：--prefix／--preset（google-oauth＝GOCSPX-、openai＝sk-、anthropic＝sk-ant-、github＝ghp_／github_pat_），沒有前綴要明寫 --any-format
  • 交付：subprocess 不經 shell，值走 stdin；wrangler 目標強制 --account（寫入 CLOUDFLARE_ACCOUNT_ID），worker 強制 --name
  • 輸出：wrangler 的 stdout／stderr 遮蔽值與任何 6 字元連續片段後，只取最後一行；--target cmd 不轉述輸出
  • 收尾：外層 finally 用 pbcopy 清空剪貼簿並驗 0 bytes，清空時忽略 SIGINT／SIGTERM／SIGHUP
  • 名稱參數用 regex 全字比對，禁止 - 開頭

來源

  • Cloudflare：Wrangler commands（pages secret put、secret put）
  • Cloudflare：System environment variables（CLOUDFLARE_ACCOUNT_ID）
  • Cloudflare：Install and update Wrangler
  • GitHub CLI：gh secret set
  • GitHub：GitHub's token formats
  • Apple：AppleScript display dialog（hidden answer）
