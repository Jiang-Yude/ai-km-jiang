AI 工作流 / 教學

只用 Codex，也能建立自己的自動工作日誌

發佈 2026-06-16 ｜ 最後更新 2026-06-16

很多人開始用 AI Agent 之後，會很快遇到一個問題：今天明明做了很多事，到了晚上卻說不清楚自己到底完成了什麼。這篇先把路線分清楚：只用 Codex，就用它的預設自動化；同時用多款 Agent，才需要一套跨 Agent 的工作鏡子。

發布：2026-06-16更新：2026-06-16
適合誰

剛開始用 Codex、想讓它幫你整理每天做了什麼的人；有很多 AI 對話和檔案變動、晚上常常斷片的人；聽過 Hermes、工作鏡子但不確定自己需不需要的人。

解決什麼問題

用 AI 做完一輪事，工作痕跡散在對話、檔案、資料夾裡，晚上說不清楚今天完成了什麼，隔天也不知道從哪裡接。

你可以帶走什麼

一個判斷原則（只用 Codex 就用自動化）、一個升級原則（多 Agent 才上工作鏡子）、三份可直接複製的提示詞，以及一個從手動到自動的三階段練習。

先問一個問題：你是單一 Agent，還是多 Agent？

我現在會把 AI 工作記錄分成兩種情況。先判斷自己是哪一種，再決定工具。工具選太早，系統會變重；判斷清楚後，工具會自己長出來。

路線 A · 只用 Codex

你的答案大多是「是」就走這條

  • 我主要只開 Codex 工作
  • 我的檔案修改大多由 Codex 完成
  • 我只是想每天知道自己做了什麼
  • 我還不需要記錄不同 Agent 的分工
  • 我希望越簡單越好

路線 B · 多 Agent 工作鏡子

你的答案大多是「是」就走這條

  • 我會同時用 Claude Code、Codex、Gemini 或其他 Agent
  • 我常常不知道哪個 Agent 改了哪裡
  • 我想追蹤任務花了多少時間和 token
  • 我想知道某個任務有沒有後續
  • 我需要把工作軌跡回寫到知識庫或工作日誌
如果你只用 Codex，用 Codex 預設自動化。如果你用多款 Agent，用跨 Agent 工作鏡子。這樣就好。

很多人一開始會把系統做太大

很多人剛開始學 AI 自動化，會想一步到位。他會想：要不要裝一個獨立的監控工具？要不要每 20 分鐘自動整理一次？要不要記錄 token、專注力、操作頻率？要不要同時接 Claude、Codex、Gemini？

這些問題都可以做。但對大多數剛開始的人來說，第一步是先讓自己看得見每天的工作軌跡。先回答三個問題就夠了：

  1. 我今天做了什麼？
  2. 我改了哪些檔案？
  3. 明天下一步是什麼？

如果這三個問題每天都能回答，你的 AI 工作流就已經開始有形狀了。

Codex-only 路線：用預設自動化就好

如果你只用 Codex，我會建議從三個階段開始。先養成習慣，再交給自動化。

第一階段手動叫 Codex 寫日誌

工作告一段落，就叫 Codex 幫你整理剛剛做了什麼。重點是建立「工作要留下痕跡」的習慣。

第二階段讓它看今天的檔案變動

手動穩了，就讓 Codex 每天根據對話、改過的檔案、產出的文件整理成日報。

第三階段定時任務自動記錄

知道日誌長什麼樣子後，設一個定時任務，每隔固定時間自動記一次。預設 30 分鐘，可調成 15 分鐘或 1 小時。

第一階段：手動叫 Codex 寫工作日誌

一開始先不要自動化。先養成習慣：工作告一段落，就叫 Codex 幫自己整理剛剛做了什麼。可以直接貼這段提示詞：

第一階段 · 手動整理
請幫我整理剛剛這段工作的工作日誌。

請分成五段：
1. 我原本要做什麼
2. 實際完成了什麼
3. 改了哪些檔案或產出了哪些東西
4. 過程中卡在哪裡
5. 下一步應該做什麼

請只記錄已經發生的事，不要幫我腦補成果。
如果你不確定，就標註「未確認」。

很多人以為工作日誌是寫給老闆看的，其實工作日誌首先是寫給明天的自己看的。尤其用 AI 做事，今天一次對話可能改了十幾個地方，不記下來，隔天很容易不知道這段工作接到哪裡。

第二階段：讓 Codex 看今天的檔案變動

等手動記錄穩了，就讓 Codex 每天幫你看今天做了什麼。提示詞可以改成：

第二階段 · 每日日報
請幫我整理今天的工作日誌。

請根據今天的對話、修改過的檔案、產出的文件，整理成一篇日報。

請包含：
1. 今日主要任務
2. 每個任務花在哪些檔案或輸出上
3. 哪些事情已完成
4. 哪些事情還沒完成
5. 明天最適合接續的三件事

限制：
- 不要寫成漂亮心得文
- 不要替我補沒有發生的成果
- 不確定的地方請寫「未確認」
- 如果有檔案路徑，請直接列出

這一步會讓你開始理解：AI 可以變成工作回顧工具，回頭看你今天的行動，把散掉的脈絡收起來。

第三階段：用 Codex 定時任務自動記錄

等你已經知道日誌長什麼樣子，再把它變成定時任務，每隔固定時間自動記一次。我自己預設每 30 分鐘記一次，你可以照自己的工作節奏調成 15 分鐘或 1 小時。提示詞可以這樣寫：

第三階段 · 定時任務（預設 30 分鐘）
請整理最近這段時間的 Codex 工作日誌。

請檢查自上次記錄到現在，這個工作區內的主要活動，整理成一段可回顧的工作日誌。

輸出格式：

# 工作日誌（這段時間）

## 完成了什麼
- 條列這段時間完成的任務

## 檔案與產出
- 列出這段時間新增或修改的重要檔案

## 卡點
- 列出過程中出現的錯誤、等待、未完成事項

## 下一步
- 接下來最適合接續的 3 件事

## 可信度
- 高：有檔案或明確對話證據
- 中：有對話脈絡但沒有落檔
- 低：只有零散線索

規則：
- 只記錄這段時間實際發生的事
- 不要補我沒有說過的成果
- 不要寫成勵志心得
- 找不到資料就寫「這段時間沒有足夠紀錄可整理」

這樣就已經是 Codex-only 的自動工作日誌。對很多人來說，這個版本已經很夠用。

那什麼時候需要多 Agent 工作鏡子？

當你的工作開始分散到多個 Agent，就會出現新的問題。

例如：Codex 幫你改檔案、Claude Code 幫你順稿、Gemini 幫你查資料、NotebookLM 幫你整理來源、Hermes 幫你定時回顧。這時候你會發現，每個工具都只知道自己那一段。Codex 不一定知道 Claude Code 剛剛做了什麼，Gemini 查到的資料可能存在另一個地方。

這時候就需要一個跨 Agent 工作鏡子。它的任務是把不同工具留下的痕跡集中起來，回答幾個更細的問題：

  • 這段時間有哪些 Agent 參與？每個 Agent 做了什麼？
  • 哪些檔案真的被改了？哪些只是對話，還沒有落檔？
  • 這個任務有沒有工作日誌？前因後果是什麼？
  • token、操作次數、專注力成本大概是多少？
這就會從「工作日誌」升級成「工作軌跡系統」。先判斷自己是哪一種，再決定工具。

給初學者的最小練習

如果我要教初學者，我會先給他們一個很小的練習。今天不要做完整自動化，只做這一件事，工作結束後對 Codex 說：

最小練習 · 10 行收尾
請幫我用 10 行以內整理剛剛這段工作：

1. 我做了什麼
2. 產出了什麼
3. 下一步是什麼

只寫事實，不要寫心得。

這個練習看起來很小，但它會讓你開始理解一件事：AI 工作流要包含兩個動作，任務開始時下指令，任務結束時收尾。開始時下指令，結束時寫紀錄，這兩個動作加起來，才會形成可以累積的工作流程。

再往前一步：讓工作日誌變成技能包

等一個人連續寫了一段時間的工作日誌，就會開始看到重複模式。例如每次寫文章都會先倒口述、再請 AI 收斂架構；每次做網站都會先改本機、再部署、再驗收。這些重複模式，就是技能包的原料。

所以我會把工作日誌視為 AI 工作流的地基。沒有工作日誌，技能包容易變成憑空想像的 SOP；有工作日誌，技能包會從真實工作長出來。

常見的坑

四個最常踩到的地方，展開看對策。

坑一：一開始就做太大的系統

剛開始只需要每天一篇工作日誌。先不要急著追 token、專注力、操作頻率，那些都是進階層。

坑二：把工作日誌寫成心得文

工作日誌的第一任務是記錄事實。可以有反思，但不要讓反思蓋過事實。尤其是自動化產出的日誌，要先能回答「做了什麼」。

坑三：只相信狀態顯示成功

任何自動化都要驗收。不要只看系統顯示成功，要看它有沒有真的寫入檔案、有沒有寫對地方、有沒有把錯誤訊息當成工作內容。

坑四：沒有下一步

好的工作日誌一定要留下下一步。因為明天的你需要一個可以接著做的入口。

給自己的定位提醒

我會把 Codex-only 看成入門路線。先讓每個人都能用 Codex 建立自己的工作日誌，等他們開始同時使用多款 Agent，再教多 Agent 工作鏡子。這樣學習成本最低，也最符合真實工作節奏。

AI 工作流的本質，就是把一次次工作留下來，變成下一次可以接續、可以複用、可以教給 AI 的流程。
