Live Skill Package / First Principles

活的馬斯克技能包

給創業者、主管、老闆使用的第一性原理顧問。

每天用 Codex 自動更新一次。我會把公開資料抓進來，整理成 live-data，讓這個技能包持續靠近最新脈絡。新聞只作參考提醒，正式技能包本體仍需要人工審核後才會更新。

下載技能包 看自動更新機制

我做這個技能包的定位很清楚：把馬斯克常見的思考方式，整理成一個可以被 AI 調用的第一性原理顧問。它服務的是思考訓練、決策反問與資料追蹤，新聞內容只放在參考層。

Core 第一性原理

把問題拆回最底層的事實、限制、成本、物理或商業條件，再重新組合解法。

Use Case 決策反問

當你卡在策略、產品、組織或資源配置時，讓 AI 先問出真正的約束與盲點。

Live Data 每日更新

每天抓取公開資料，分成本人直接內容、公司一手資訊、新聞報導與新聞評論。

創業者、主管、老闆可以怎麼用

這個技能包最適合放在「要做重要判斷之前」。它會先把你的問題拆開，逼你看見背後的前提，暫時放下名言式的漂亮答案。

Founder 創業者：拆產品與市場假設

你可以拿來檢查新產品、新服務、新課程。它會追問你：這個痛點是事實，還是你希望它是事實？使用者現在用什麼替代方案？你解的是需求，還是只是包裝一個功能？

Manager 主管：拆團隊瓶頸

你可以拿來看團隊流程、交付速度、溝通成本。它會追問你：真正卡住的是人力、資訊、權限、工具，還是目標本身不清楚？

Owner 老闆：拆資源配置

你可以拿來判斷要不要開新線、砍舊案、投入自動化。它會追問你：最小可驗證行動是什麼？如果預算只剩三分之一，哪一件事仍然要做？

Operator 營運者：拆例行工作的必要性

你可以拿來檢查哪些流程可以被 AI 接住，哪些環節仍需要人判斷。它會追問你：這一步是在創造價值，還是在維持習慣？

第一性原理顧問會怎麼反問你

我希望這個技能包的核心能力，是會反問。它不急著給答案，會先把問題拆回更底層。

  • 這個問題裡，哪些是你親眼驗證過的事實？哪些只是市場、團隊或你自己反覆講久了的假設？
  • 如果把既有做法全部拿掉，只留下目標與限制，最小可行路徑是什麼？
  • 你現在最想保護的東西，是客戶價值、團隊情緒、既有流程，還是你已經投入的沉沒成本？
  • 如果這個方案失敗，最可能先壞掉的是哪個環節？需求、成本、供應、交付、信任，還是速度？
  • 你要的是更漂亮的答案，還是一個可以被現實測試的小實驗？
我稱它為靈魂考驗它的目的，是協助使用者把問題盲點看清楚。很多時候，真正有價值的地方不在答案，而在那個讓人停下來重想的問題。

Codex 每日自動更新機制

這個 repo 有 live-data。我每天用 Codex 自動更新一次，把新的公開資料抓進來。每日任務只更新資料層，不會直接改正式技能包本體。

01 抓公開資料

Google News RSS、公司與公開來源、Elon Musk 公開 X 個人頁上看得到的內容。

02 分類來源

分成本人直接內容、公司一手資訊、新聞報導、新聞評論，避免混在一起看。

03 產出 daily digest

每天生成 digest 與 raw JSONL，保留原始資料與摘要，方便回查。

04 人工月度統整

每月再統整一次。正式更新技能包，需要過 promotion gate，不讓每日新聞直接改人格核心。

分類 意思 使用方式
musk_direct Elon Musk 本人公開可見的內容，包含公開 X 個人頁上看得到的內容。 優先作為本人直接脈絡，但仍保留來源時間與原始連結。
company_primary 公司或官方一手來源，例如公告、部落格、新聞稿。 用來補足公司決策、產品與技術進展。
news_report 新聞媒體的事實報導。 只作參考提醒，不能直接視為本人立場或技能包結論。
news_commentary 評論、分析、觀點型文章。 標清楚是評論資料，用來觀察外部解讀，不做價值判斷。
新聞資料的免責說明新聞與評論可能有角度、爭議或時效差。每日更新會把它標成參考資料，提醒讀者這是媒體內容，不代表 Elon Musk 本人說法，也不代表我替內容背書。
為什麼不每天改 SKILL.md正式技能包本體會影響 AI 的思考方式。如果每天被新聞推著改，很容易把短期事件寫成人格核心。所以每日任務只更新 live-data，每月再統整一次，重要內容進 review queue，通過 promotion gate 後才更新正式技能包。

這個技能包適合怎麼問

你可以把它當成一個第一性原理顧問，直接丟你的真實問題。越具體，越有用。

範例問法我現在想推出一個給中小企業主管的 AI 工作流課程。請用第一性原理拆解這個產品，先不要給行銷文案，先反問我最需要釐清的十個問題，並指出哪些是我可能自以為成立的假設。

如果你正在做產品、課程、服務、團隊管理或公司決策，它可以幫你把問題拆小，把假設攤開，把下一步變成可以驗證的行動。
