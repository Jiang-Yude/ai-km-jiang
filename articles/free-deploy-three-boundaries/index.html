網頁部署 / 存取控制

我以為沒人知道網址就夠了：盤點自己 74 個網站那天

六個含客戶會議記錄的頁面，網址是亂碼、沒掛在任何地方，我一直以為那樣就夠了。

這篇在講什麼

很多人把網頁放上網之後，用「網址很難猜、沒掛在任何地方」當作保護。這是障礙，不是門鎖。這篇拆開免費部署的三道邊界：哪一層免費就夠、哪一層要加設定、哪一層真的要付錢，並給出一個三分鐘就能做完的自查法。

適合誰

  • 用 AI 幫你做網頁，但不確定「這樣放上去安全嗎」的人
  • 做課程、接案、顧問，有些內容只想給特定人看的一人公司
  • 已經放了十幾個頁面上網，但說不出哪些對 Google 開放的人

你會得到什麼

  • 一個判斷順序：三個問題決定你該用免費、加設定、還是付費
  • 兩平台存取控制的完整價格對照，含官方來源
  • 三分鐘自查法：打開任何一頁，馬上知道它對搜尋引擎開不開放
  • 一段可複製的提示詞，讓 AI 幫你盤點手上所有頁面

真實現場

前幾天我盤點自己的 Vercel 帳號，發現上面有 74 個網站。

這個數字本身讓我意外。做網頁太容易了，一行指令就上線，做完就忘了它存在。但更意外的是後面查到的東西。

我把每一個站抓下來，檢查它有沒有設 noindex。結果有六個站對 Google 完全開放：

  • 一份「會議報告書：江昱德 x Vicky」
  • 一份「江江與芝芝討論」的工作坊報告
  • 兩份永力扶輪社的會議記錄，其中一份標題就寫著「兩次會議人員態度軌跡」
  • 一份永力扶輪社的 AI 導入與永續報告書規劃
  • 一份旅學堂的 2026 影響力報告

這些都是客戶會議內容，有真實人名、有對合作對象的判讀。

它們的網址都是亂碼，沒有掛在我任何一個頁面上，也沒有傳給第三個人。我一直以為那樣就夠了。

實際上它們對搜尋引擎完全開放，只是還沒被爬到而已。

問題來源

事後回想，我踩的是三個不同的坑，而且它們常常同時發生。

一、把「找不到」當成「進不去」

亂碼網址的作用是降低被亂找到的機率。它是一道障礙，可以擋掉隨手亂試的人。

但它擋不住任何一種真正的外流：連結被轉貼、被截圖、被存進瀏覽器書籤同步到別的裝置、被 AI 助理讀進脈絡。任何一種情況發生，那個網址就是一個公開網址。

二、以為部署工具會幫你把關

我用的是 Vercel 的免費方案。它預設什麼保護都沒有，部署上去就是公開的。

這不是平台的錯，它從來沒說會幫你擋。是我自己沒去確認預設值。

三、沒查過真正的保護要多少錢

這一項最關鍵。我從來沒認真查過「如果我要密碼保護，多少錢」，所以我心裡一直有個模糊的假設：需要的時候再加就好。

查完之後發現，那個「需要的時候」的價格是每月 170 美元。

機制解法：先問這頁要給誰看

與其問「該用哪個平台」，先問「這頁要給誰看」。答案分三層，每一層撞到不同的邊界。

第一道邊界：完全公開的內容

作品集、公開文章、活動頁、對外簡介，任何人看到都沒關係。

這一層兩個平台的免費方案都夠用，額度比多數人想像的寬：

  • GitHub Pages 免費：網站不超過 1 GB、每月 100 GB 流量、每小時 10 次建置（都是軟性上限）
  • Vercel Hobby：每月 100 GB 流量、每小時 32 次建置、每日 100 次部署

兩邊都免費支援自訂網域與自動 HTTPS。

這一層的選擇標準很單純：你的檔案本來放在哪，就用哪個。

只有一個差別要注意。GitHub Pages 的免費方案要求 repository 必須公開，所以原始碼會跟著公開。如果你的 HTML 裡有客戶名稱的註解、還沒公布的日期、內部備註，那些也在網路上。

第二道邊界：不想被搜到，但被看到沒關係

課程的課後資料、活動的內部通知、還在校稿的頁面，都屬於這一層。

做法是 noindex，兩個平台都免費，加一行就好：

<meta name="robots" content="noindex, nofollow">

搭配 robots.txt 的 Disallow: /，搜尋引擎就不會收錄。

這裡有個 Google 官方文件講得很直接、但很多人沒讀到的重點：noindex 只阻止頁面出現在搜尋結果，知道網址的人仍然可以直接打開。

換句話說，這一層處理的是「找不到」。如果你要的是「進不去」，那是第三層。

第三道邊界：只給特定人看

這一層要付費，而且價差很大。以下是查官方文件整理出來的完整選項。

Vercel

  1. Vercel Authentication：Hobby 免費就有，但只保護 preview 網址，正式網址仍然公開
  2. Shareable Link：可撤銷的通行連結，Hobby 全帳號限一條
  3. Password Protection：保護正式網址，需要 Pro 加購 Advanced Deployment Protection，每月 20 美元加 150 美元，最低 170 美元
  4. Trusted IPs：IP 白名單，只有 Enterprise，客製報價

GitHub Pages

  1. private repository：GitHub Pro 每月 4 美元，但這只隱藏原始碼，發布出去的網站預設還是公開的
  2. 私密發布（只限 repo 成員進入）：需要組織版 Enterprise Cloud，每位使用者每月 21 美元起

第二點是很多人誤會的地方。付了 GitHub Pro，你得到的是「程式碼不公開」，不是「網站不公開」。

它保證什麼、不保證什麼

這段是我踩坑之後最想寫下來的。

noindex 保證的

  • 頁面不會出現在 Google 搜尋結果
  • 已經被收錄的頁面，重新爬取後會移除

noindex 不保證的

  • 擋不住任何知道網址的人
  • 擋不住連結外流
  • 對非搜尋引擎的爬蟲，行為沒有官方保證

亂碼網址保證的

  • 降低被隨機猜中的機率

亂碼網址不保證的

  • 一旦外流，跟公開網址沒有差別
  • 我查不到 GitHub 官方對「秘密網址是否算安全措施」的任何正式說明，也就是說沒有人背書這種做法

免費方案的條款邊界

這一項跟技術無關，但對一人公司很重要。

Vercel Hobby 的使用條款寫明只允許個人、非商業用途。官方在定價頁與條款都提到，商業用途、接案、付費服務、業務網站應該採用 Pro。這條規定跟流量多寡無關，就算你的站每月只有幾十次瀏覽，用途是商業的就已經越界。

GitHub Pages 也有類似邊界，官方明講不允許把它當成免費主機經營「主要用於商業交易」的網站、電子商務或商業 SaaS。

還有一個更實際的風險：Vercel Hobby 超出免費額度時，官方處理方式是暫停整個帳號的新舊部署，通常要等 30 天恢復，而且免費方案不能加購少量超額流量。流量突然衝高的那一天，你的站會全部下線，沒有花錢解決的選項。

你可以怎麼開始

三分鐘自查法

拿你手上任何一個已經上線的頁面，做這三步：

  1. 用瀏覽器打開它，按 Cmd+U（Windows 是 Ctrl+U）看原始碼
  2. 按 Cmd+F 搜尋 noindex
  3. 找不到，代表這頁對搜尋引擎完全開放

然後問自己一句話：這頁如果被完全不相關的人搜到，會有問題嗎？

會有問題、而你以為它是私密的，那就是你最該先處理的那一頁。

三個問題的判斷順序

要決定新的頁面該怎麼放，照這個順序問：

問題一：這頁有沒有不能被外人看到的東西？

沒有，走第一層，兩個平台免費都夠用，選你檔案本來放的那個。有，繼續問。

問題二：你能接受「知道網址的人看得到」嗎？

能接受，走第二層。noindex 加不公開的網址，兩邊都免費。適合課後資料、內部通知這類「不想被搜到，但流出去也不會出事」的內容。不能接受，走第三層，要付費。

問題三：這個用途算商業嗎？

算，Vercel 該用 Pro。這跟流量無關，是條款問題。

可複製提示詞：讓 AI 幫你盤點

如果你手上已經有一堆頁面，不用一個一個開。把這段貼給你的 AI 助理：

我要盤點手上所有已上線的網頁，判斷哪些需要補防護。

請幫我對以下每個網址做三件事，用表格回報：
1. 抓取首頁，檢查 head 裡有沒有 <meta name="robots"> 且含 noindex
2. 抓取 /robots.txt，檢查有沒有 Disallow: /
3. 抓取 <title>，讓我知道這頁是什麼

回報格式：網址 | 標題 | 有無 noindex | 有無 Disallow | 我的判斷（需要防護／不需要）

判斷標準：標題或內容含真實人名、會議、報價、客戶名稱、
內部評估的，都算需要防護。純公開展示、作品集、活動頁不用。

網址清單：
[貼上你的網址]

跑完你會拿到一張表，一眼看出哪幾頁該補。

收尾 Recap

  • 免費部署的邊界有三道，對應「完全公開」「不想被搜到」「只給特定人」三種需求
  • 前兩道免費就能做到，第三道要付費，最低每月 170 美元（Vercel）或 21 美元一人（GitHub 組織版）
  • noindex 擋搜尋，不擋存取。亂碼網址是障礙，不是門鎖
  • Vercel Hobby 條款只允許非商業用途，這跟流量無關
  • 自查只要三分鐘：Cmd+U 搜 noindex

常見的坑（與對策）

坑一：以為 private repository 等於私密網站

對策：分清楚兩件事。private repo 保護的是原始碼，網站本身要另外設。GitHub 要讓網站只限授權者進入，需要組織版 Enterprise Cloud。

坑二：把敏感內容放上網，打算「之後再加保護」

對策：先查那個「之後」要多少錢。我就是沒查，才以為隨時可以加。查完發現是每月 170 美元。

坑三：只檢查首頁，忘了子頁

對策：noindex 是逐頁生效的。首頁有設不代表 /report/ 有設。用上面那段提示詞跑完整清單。

坑四：以為流量小就不會有事

對策：條款限制跟流量無關。而且免費額度爆掉時，Vercel 的處理是暫停整個帳號，不是只擋超額的部分。

給自己的定位提醒

查完這一輪，我最後的做法不是去買 170 美元的保護。

我把自己的內容分成三類：公開官網（要被搜尋引擎收錄，也要被 AI 引用）、半私密站（亂碼網址加 noindex，我知道它擋搜尋不擋存取，所以只放「流出去也不會出事」的東西）、完全不上網（分潤談判、內部評估、對客戶未公開的判讀，留在本機知識庫）。

第三類是關鍵。與其把敏感內容放上網再想辦法保護，先判斷它該不該上網。

那 170 美元一個月的密碼保護我沒買，是因為需要那種保護的內容，我一開始就不該放上去。

這個判斷順序省下的不只是錢。少一個對外的入口，就少一個要維護、要記得檢查的東西。

工具會換，方案會漲價，條款會改。但「這份內容該給誰看」這個判斷，是你自己的，不會過期。
