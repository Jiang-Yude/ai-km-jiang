網頁部署 / 平台選擇

AI 幫你把網頁做好了，該放哪？GitHub Pages 與 Vercel 完整比較

兩個都免費、都支援自訂網域，差別在你用了三個月之後才會浮出來的細節。

這篇在講什麼

不會寫程式的人，現在用 AI 幾分鐘就能做出一個網頁。做完之後會卡在同一個問題：這東西要放哪裡才看得到？兩個最常見的免費選項是 GitHub Pages 與 Vercel。這篇先給你三個判斷問題，再用四層配置示範怎麼分，最後才附上完整的額度與費用查詢表。

適合誰

  • 用 AI 做好了網頁，不知道該放哪個平台的人
  • 已經在用其中一個，但不確定另一個是不是更適合的人
  • 做課程、接案、顧問，有些內容只想給特定人看的一人公司

你會得到什麼

  • 三個判斷問題，照著問就知道該選哪個
  • 四層配置的分類方式，可以直接照抄
  • 權限控制的六種做法，依「你想讓誰看到」排列，含實際費用
  • 一段可複製的提示詞，讓 AI 幫你盤點手上所有頁面

一個具體問題

你請 AI 幫你做了一個網頁。可能是課程的報名頁、給客戶看的提案、自己的作品集。

檔案做好了，在你的電腦裡。接下來的問題是：怎麼讓別人打得開？

搜尋「免費網頁空間」會跳出十幾個平台，每個都說自己最簡單。對「用 AI 做網頁」這個情境來說，主流就兩個：GitHub Pages 與 Vercel。兩個都免費、都支援自訂網域、都有自動 HTTPS，AI 也都很會操作。

差別在細節，而那些細節會在你用了三個月之後才浮出來。

這兩個平台都用自己的名字稱呼方案等級，第一次看會有點卡。先對照一下：

先做三個判斷

免費額度通常不是第一個門檻。公開程度、商業用途與未來功能，才會真正改變選擇。

01 誰能看到？

完全公開、降低曝光，或只限授權者？

02 是否商用？

接案、付費課程與業務網站，需要先核對方案條款。

03 未來要加什麼？

純展示頁，或可能增加表單、後端與會員功能？

這三個問題的答案決定一切。下面先看怎麼分層，再看每一層的技術細節。

四層配置：我自己怎麼分

我目前有四十幾個網站在線上，依內容敏感度分成四層。這套分法你可以直接照抄。

第 1 層｜完全公開

GitHub Pages

適合：作品集、demo、開源技能包說明

特性：公開、長期不動、方便分享。原始碼跟著公開也無所謂

第 2 層｜降低曝光

半私密 Vercel

適合：含人名、會議、定價的交付頁

做法：亂碼網址、noindex、robots.txt 的 Disallow，三件一起做

這一層降低被發現的機率，沒有形成真正的存取控制。

第 3 層｜主動公開

公開官網 Vercel

適合：品牌官網、公開文章、服務介紹

目標：讓搜尋引擎與 AI 能找到、理解與引用，完全不設 noindex

第 4 層｜不發布

完全留在本機

適合：分潤談判、內部評估、敏感策略

有些內容不需要找部署平台。留在本機就是一個清楚的安全決策。

第四層是關鍵。與其把敏感內容放上網再想辦法保護，先判斷它該不該上網。

分層這件事，我在知識庫上也做過一次
  • 知識庫太大，我改成三庫分流　這篇談的是網站該放哪一層，那篇談的是檔案該放哪一庫，兩邊用的是同一種判斷邏輯。

三個關於權限的常見誤解

分層之前，先破除三個最多人搞錯的觀念。這三件事我自己都誤會過。

誤解一

「加了 noindex 就是私密的」

Google 官方文件寫得很直接：noindex 只讓頁面不出現在搜尋結果，知道網址的人仍然可以直接打開。

誤解二

「付了 GitHub Pro，網站就不公開了」

GitHub Pro（付費版）的 private repository 藏的是原始碼。網站發布出去之後預設還是公開的。要讓網站本身只限授權者，需要組織版 Enterprise Cloud。

誤解三

「Vercel 免費就有帳號驗證」

免費版的 Vercel Authentication 只保護 preview 網址。你給客戶的那個正式網址不在保護範圍內。

共同點是：「不被搜到」跟「別人進不去」是兩件事。

一人公司要先看這段：商業用途條款

Vercel 免費版（Hobby）的使用條款寫明只允許個人、非商業用途。官方在定價頁與條款都提到，商業用途、接案、付費服務、業務網站應該採用付費版 Pro，每月 20 美元起。

這條規定跟流量無關。就算你的站每月只有幾十次瀏覽，用途是商業的就已經越界。

GitHub Pages 也有類似邊界，官方明講不允許把它當成免費主機經營「主要用於商業交易」的網站、電子商務或商業 SaaS。

另一個實際風險：Vercel 免費版超出額度時，官方處理方式是暫停整個帳號的新舊部署，通常要等 30 天恢復，而且不能加購少量超額流量。流量突然衝高的那一天，你的站會全部下線，沒有花錢解決的選項。

兩個平台各適合長成什麼樣

GITHUB PAGES 穩，但要公開

GitHub 本來是給工程師存放程式碼的地方，Pages 是它附帶的功能：把你的資料夾直接變成一個網站。

背後是 Microsoft，免費方案多年沒有大改，適合放長期不太會動的東西。

限制來自出身。它的核心是「公開分享程式碼」，所以免費方案要求你的檔案必須公開。純靜態，沒有後端。

VERCEL 快且有彈性，但條款較嚴

給現代網站用的部署平台。全球都有伺服器，台灣連過去很快。

不只能放靜態網頁，支援 Serverless Functions，未來想加登入、表單、會員功能都有空間。

限制在條款跟額度。免費方案有明確的用途限制，超額的處理方式也比較硬。

Vercel 現在同時看流量與「Edge Requests」

這是 2024 年 4 月起的改變，官方把原本主要看頻寬的模型拆成多個獨立指標：Fast Data Transfer、Edge Requests、Function Invocations 等各自計量。理由是讓每種資源能分別最佳化，按實際使用量計價。

對免費版使用者的實際影響是：你現在有兩條可能先撞到的線。而且 Vercel 的方案文件頁把 Edge Requests 放在顯眼位置、沒有列出頻寬，很容易讓人以為頻寬那條不見了。它還在，只是要去 pricing 頁才看得到。

指標免費版上限什麼樣的網站會先撞到
Fast Data Transfer（流量）100 GB／月檔案大：影片、PDF、高解析原圖、大型下載
Edge Requests（請求數）100 萬次／月檔案多但小：大量 JS 分塊、圖片、API 輪詢、爬蟲探測
Function Invocations100 萬次／月有後端邏輯的網站
可建幾個專案200 個用 AI 大量產站的人
Edge Request 是什麼

每個到達 Vercel 的檔案請求都算一次。一次頁面首度載入通常十幾到二十幾次，因為 HTML、CSS、JS、每張圖、字型各算一次。

100 萬次大概是多少

以每次載入 20 個請求估算，約 5 萬次冷載入。但這是請求容量換算，不等於訪客數，實際數字受快取、預抓與爬蟲影響很大。

怎麼看自己用了多少

Vercel 後台 Usage 頁看得到當月累計。兩條線都要看，別只盯其中一條。

超額的處理方式：免費版沒有小額加購的緩衝。多數月度資源超額後，相關功能或專案可能被暫停，通常要等 30 天或升級。要注意的是每日部署 100 次是另一條不同的限制，命中後等一天就恢復，不是 30 天。

關於長期穩定度，坊間有不少沒根據的說法，這裡誠實講清楚：GitHub Pages 本次查證未找到 2023 到 2026 年間縮減免費額度的官方公告，這只能說「查無縮減紀錄」，不能說「保證不會變」。Vercel 常見的「2023 年縮減過免費額度」說法查無官方公告，那年的變更是 Pro 的 Function timeout 降到 15 秒，官方同時明寫免費版維持原設定；真正有紀錄的縮減是 2026 年，免費版的部署保留期改為 30 天。

如果你的目標是「被 AI 找到」，選平台的邏輯要反過來

前面講的都是一般情況。但有一種人要用相反的邏輯選平台，而且這種人越來越多。

如果你在做內容，而且希望被 AI 搜尋引用（放 sitemap、寫 llms.txt、加 JSON-LD、主動邀請爬蟲來讀），那你歡迎的正是爬蟲流量。

問題來了：Vercel 每個到達的檔案請求都算一次 Edge Request，包括 AI 爬蟲的。

也就是說，你的內容策略做得越成功，AI 爬蟲來得越勤，你越接近免費版的上限。

這個落差有多大

Vercel 官方在 2024 年 12 月公布過一組數字：GPTBot 一個月在他們的網路產生 5.69 億次請求，Claude 產生 3.7 億次，兩者合計約為同期 Googlebot 的 20%。

落到單一網站上會長成這樣（以下為 Vercel 官方社群與開發者社群的公開案例，屬使用者自陳）：

案例一

某目錄型網站只有 4,905 次人類頁面瀏覽，卻產生 54.3 萬次 Edge Requests。原因是它有約 7,500 個可被爬蟲遍歷的頁面。

案例二

一個免費版專案一夜之間收到 ClaudeBot 88.2 萬次、GPTBot 12.5 萬次，Edge Requests 衝到 150 萬，專案被暫停。

案例三

有開發者回報 Meta 的爬蟲一個月對他的網站發出 1,100 萬次請求。

注意案例一的比例：人類瀏覽與請求數差了一百倍以上。如果你只看「我的網站沒什麼人看」就以為安全，會判斷錯。

四個平台對「歡迎爬蟲」型網站的差別

平台靜態檔案請求怎麼算對想被 AI 引用的網站
Cloudflare Pages免費且不限次數，只有執行 Worker 才計量爬蟲來多少都不影響額度
GitHub Pages不按請求數計費，只有每月 100 GB 軟性上限也沒有請求數風險
Vercel每次都算 Edge Request，免費版每月 100 萬次爬蟲越多越接近上限
Netlify算（每 1 萬次請求扣 2 credits）同 Vercel 的方向

一個反直覺的結論

回頭看前面那張表，GitHub Pages 免費版最大的限制是「原始碼必須公開」。

但對一個以「被 AI 找到」為目標的內容網站來說，這根本不算限制。你的內容本來就要讓全世界看到，公開原始碼沒有損失。

換句話說，同一個特性，在不同目標下的評價完全相反。這也是為什麼我不建議你照抄任何一篇「哪個平台比較好」的結論，包括這一篇。先確定你的目標，那張表的每一格才有意義。

那該不該搬

講我自己的判斷，供你對照。我的知識官網目前還在 Vercel，短期不打算搬，三個理由：

  1. 距離上限還很遠。這是「知道就好」的等級，不是「現在就動」。
  2. 官網不只是靜態頁。有互動腳本、自動互聯機制，搬家要重新驗證這些跑不跑得起來。
  3. Vercel 有 Firewall，被擋掉的請求官方明說不計入 Edge Requests。但這個解法跟目標矛盾，我要 AI 讀我，不是擋它。

會讓我改變決定的訊號很明確：後台 Usage 頁的 Edge Requests 逼近 50 萬次／月。那時候要做的第一件事是去 Observability 看流量來源，先分清楚是人、是 AI 搜尋爬蟲、還是不需要的爬蟲，再決定要擋、要搬、還是要升級。

機器讀你的內容這件事，我另外寫過一篇
  • 網路上一半以上的訪問已經不是人了，你的內容準備好被機器讀了嗎？　那篇談的是怎麼讓機器讀懂你的內容，這一段談的是機器來讀之後，帳單長什麼樣子。

一個我踩過的坑

上面那套四層配置是踩過坑之後才定下來的。

前幾天我盤點自己的 Vercel 帳號，發現有六個站對 Google 完全開放，包括兩份客戶會議報告、一份工作坊記錄、一份影響力報告。

它們的網址都是亂碼，沒掛在任何頁面上，也沒傳給第三個人。我一直以為那樣就夠了。

實際上它們只是還沒被爬到而已。

那次之後我才把第 2 層的「三件事一起做」寫成固定規則。亂碼網址只是其中一件，少了 noindex 跟 robots.txt，前面那件事沒有意義。

會出錯的系統要怎麼設計，是另一個題目
  • 與其期待不出錯的 AI 系統，不如設計能容錯的 Loop　這篇談的是設定漏了怎麼補，那篇談的是怎麼把「會漏」這件事直接設計進流程裡。

可複製提示詞：讓 AI 幫你盤點

如果你手上已經有一堆頁面，不用一個一個開。把這段貼給你的 AI 助理：

我要盤點手上所有已上線的網頁，判斷哪些需要補防護。

請幫我對以下每個網址做三件事，用表格回報：
1. 抓取首頁，檢查 head 裡有沒有 <meta name="robots"> 且含 noindex
2. 抓取 /robots.txt，檢查有沒有 Disallow: /
3. 抓取 <title>，讓我知道這頁是什麼

回報格式：網址 | 標題 | 有無 noindex | 有無 Disallow | 我的判斷（需要防護／不需要）

判斷標準：標題或內容含真實人名、會議、報價、客戶名稱、
內部評估的，都算需要防護。純公開展示、作品集、活動頁不用。

網址清單：
[貼上你的網址]

跑完你會拿到一張表，一眼看出哪幾頁該補。

只想快速檢查單一頁面的話更簡單：打開它按 Cmd+U（Windows 是 Ctrl+U）看原始碼，Cmd+F 搜 noindex。找不到就是對搜尋引擎全開。

收尾 Recap

  • 先問三個問題：誰能看到、是否商用、未來要加什麼
  • 完全公開的內容，兩個平台免費都夠用，選你檔案本來放的那個
  • GitHub Pages 免費方案會連原始碼一起公開，Vercel 可以用私人 repo
  • noindex 擋搜尋不擋存取，亂碼網址是障礙不是門鎖
  • 真正的存取控制要付費：Vercel 170 美元起、GitHub 組織版 21 美元一人起
  • Vercel 免費版條款只允許非商業用途，這跟流量無關
  • Vercel 免費版有兩條線：100 GB 流量與 100 萬次 Edge Requests，後台 Usage 頁兩條都要看
  • 第四層「不上網」是最容易被忽略、但常常最正確的選項

常見的坑（與對策）

坑一：以為 private repository 等於私密網站

對策：分清楚兩件事。private repo 保護的是原始碼，網站本身要另外設。

坑二：以為 Vercel 免費版的 Authentication 保護了正式網址

對策：它只保護 preview 網址。你給客戶的那個網址不在保護範圍。

坑三：把敏感內容放上網，打算「之後再加保護」

對策：先查那個「之後」要多少錢。我就是沒查，才以為隨時可以加。

坑四：只檢查首頁，忘了子頁

對策：noindex 是逐頁生效的。首頁有設不代表 /report/ 有設。

坑五：只盯著流量，忘了還有請求數這條線

對策：Vercel 方案文件頁把 Edge Requests 放在顯眼位置、沒列頻寬，容易讓人以為只剩一條線。實際上兩條都在，而且對圖片多、爬蟲多的網站，請求數那條通常會先撞到。

坑六：以為流量小就不會有商業用途問題

對策：條款限制跟流量無關。Vercel 免費版額度爆掉時是暫停整個帳號，不是只擋超額的部分。

給自己的定位提醒

工具會換，方案會漲價，條款會改。這篇的數字半年後可能就要重查。

但有一件事不會過期：「這份內容該給誰看」這個判斷，是你自己的。

平台只提供選項，判斷還是要你來做。而這個判斷做對了，省下的不只是錢。少一個對外的入口，就少一個要維護、要記得檢查的東西。
