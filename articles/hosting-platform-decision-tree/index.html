決策樹 / 網站上線

我的網頁是哪一種，該放哪個託管平台？｜託管平台決策樹，四個問題分出六種網頁與對應平台

照「網頁需要什麼」回答四個問題，走到六個終點之一。每個終點附上我真的放在那個平台上的網站。

用 AI 做好一頁網頁之後，下一個問題是放哪裡。Vercel、Netlify、Cloudflare、GitHub Pages、Railway、Render，每一家都說自己一鍵部署。我手上有 37 個網站分散在三個平台上，這篇把我怎麼決定放哪裡整理成一棵決策樹：回答四個問題，就會走到一個平台，每個終點附上我真的放在那裡的網站。

適合誰
  • 用 AI 做好網頁或小工具，把 localhost 網址傳給朋友，對方打不開
  • 聽過 Vercel、Cloudflare、GitHub Pages，不知道差在哪
  • 手上的網頁有密碼、有會員、要存資料，不確定免費平台放不放得下
  • 要幫客戶架站，想先搞清楚哪些平台的免費方案可以拿來做生意
你可以帶走什麼
  • 一棵可以點選的決策樹：四個問題，走到六個終點之一
  • 每個終點對應的平台、適合的網頁類型、我放在那裡的案例
  • 判斷不出來時，直接貼給 AI 的一段提示詞

先分清楚：localhost 是你自己的電腦，託管平台是一台幫你開著的電腦

AI 幫你寫完程式，瀏覽器打開的網址常常是 localhost:3000。localhost 的意思是「這台電腦自己」，朋友點開這個網址，他的手機會去找他自己的手機，當然找不到你的網頁。

要讓別人打得開，就要把網頁放到一台一直開著、有公開網址的電腦上。有三條路：

路線是什麼代價
自己家裡的電腦筆電或小主機一直不關機停電、斷網、電腦睡著網站就掛，還要自己處理資安
租雲端主機（VPS）雲端公司切一台空的虛擬電腦給你從作業系統到防火牆都要自己設定
託管平台平台把主機、環境、網址都包好，你只交檔案或程式碼要照平台的規則與額度走

對用 AI 做網頁的人，第三條路最省事。這篇只講第三條路裡怎麼選。

平台先別比規格，先回答你的網頁是哪一種

選平台最常見的卡法，是先去比各家規格，越比越亂。平台只是工具，先搞清楚自己的網頁需要什麼，答案會自己縮到一兩家。

下面四個問題照順序問。Gary Chen 在他的部署教學影片裡用了三個判斷問題：要不要後端、全端還是前後端分離、要不要 24 小時開著。我照自己 37 個站的實際情況改成四題，多加了一題「要公開還是只給特定人看」，因為我的網站有一大半是給客戶或學員看的。

點選看看：你的網頁會走到哪個平台 一題一題點答案，路線會在下方總覽圖亮起來。也可以直接點總覽圖上的終點。

    決策樹文字版
    1. 需要後端嗎？不需要 → 要公開嗎？公開 → 終點一 Cloudflare Pages；只給特定人看 → 終點二 Cloudflare Pages 加不收錄設定
    2. 需要後端 → 後端的工作多久做完？要長時間跑或一直開著 → 終點六 常駐主機平台
    3. 幾秒內做完 → 用 Next.js 這類全端框架寫的？是 → 終點五 Vercel
    4. 不是，是一般網頁加一小段伺服器程式 → 要被外部服務叫醒或定時跑嗎？等訪客來按 → 終點三 Cloudflare Pages 加 Pages Functions；要 → 終點四 Cloudflare Workers 加排程

    第一題：你的網頁需要後端嗎？

    後端是網頁背後看不見的那一段程式。判斷方法很簡單，下面任何一項答「要」，就是需要後端：

    • 要登入、要輸入密碼才看得到
    • 要把使用者填的資料、上傳的照片存起來
    • 要呼叫 AI，而 API 金鑰不能讓瀏覽器看到
    • 要接 LINE 這類外部服務的通知，或要定時自己跑

    全部都不要，就是純靜態網頁：作品集、活動介紹、課程簡介、簡報、一頁式名片。

    不確定的話，直接問幫你寫程式的 AI：「這個專案是純靜態網站，還是有包含後端運算？」

    不需要後端的網頁：再問要公開，還是只給特定人看

    終點一：公開的靜態網頁，放 Cloudflare Pages

    純靜態網頁要的只有兩件事：開得快、不會因為流量被收錢。Cloudflare Pages 的靜態檔案流量不計量（2026-09-15 查官方文件），把網頁資料夾拖上去就有網址。

    我的案例：攝影網站搬家。161 頁、一萬四千多個檔案、2.5 GB 的網站，從 Webnode 整站搬到 Cloudflare Pages。它單一檔案上限 25 MiB、每站 20,000 個檔案，這個網站都在範圍內。

    GitHub Pages 與 Vercel 也都能放靜態網頁。GitHub Pages 要注意，免費帳號只能從公開的 repo 發布，發布出去的網站也是公開的（2026-09-16 查官方文件）；它的使用條款也不允許拿它當免費主機經營線上生意（2026-08-19 查證），幫客戶做商業網站不要選它。我的 AI 名片和幾個早期 demo 在 GitHub Pages 上，還在正常運作。2026 年 8 月起，我新做的網頁預設放 Cloudflare，GitHub Pages 上的舊站只維護不新增。

    整站搬家的完整過程，我另外寫過
    • 官網搬家一個月零元：把攝影網站從 Webnode 整站搬到 Cloudflare Pages　這一段只講它為什麼放 Cloudflare Pages，那篇講搬家五步驟，以及抓站工具漏掉 65% 圖片的坑。

    終點二：只給特定人看的靜態網頁，放 Cloudflare Pages 加上不被搜尋收錄的設定

    有些頁面不想被搜尋引擎找到，但要讓收到網址的人手機點開就能看：文章草稿、會議整理、給客戶的提案頁。

    我的做法是放 Cloudflare Pages，網址取一個隨機的名字，加上「不要收錄」的設定（noindex 與 robots 全擋），不設登入。

    我的案例：

    • 文章草稿預覽站：文章上線前先推到這裡，傳網址給要看稿的人。之前用別家平台的預覽網址，對方手機一點就跳登入頁，打不開。
    • 網站放哪裡的決策頁：2026 年 9 月我自己要決定 37 個站怎麼分配，做了一頁四個問題的決策頁，也是用這個方式放上去。
    不收錄不等於上鎖拿到網址的人都看得到。內容真的不能外流，就要回到第一題，答「需要後端」，加一道密碼。
    網頁要鎖到什麼程度，我另外排過一個順序
    • 你的網頁其實沒鎖：公開資訊、付費內容、機密隱私該放哪一層　這一段只講「不收錄」這一層，那篇把六層防護排開，說清楚每一層擋得住什麼、擋不住什麼。

    需要後端的網頁：再問後端的工作多久做完

    後端有兩種運作方式。

    按一下才醒來（Serverless）

    訪客按按鈕的那一刻，雲端才啟動一小段程式，幾秒內做完就關掉。登入驗證、記一筆資料、呼叫一次 AI 都屬於這種。沒人用時不花錢，所以免費額度通常給得大方。

    要長時間跑或一直開著（常駐伺服器）

    一次要跑好幾分鐘以上的任務（例如影片轉檔），或雲端要有一台電腦 24 小時不關（例如一直在抓資料的爬蟲、多人即時聊天室），需要這種。

    終點六：要長時間跑或一直開著的，放常駐主機平台

    Gary Chen 在影片裡推薦 Railway 或 Render。這兩家都有免費方案，但免費方案會休眠或有限制，例如 Render 的免費網頁服務閒置 15 分鐘就休眠（2026-09-16 查官方文件）。要穩定常駐、不休眠，通常就要付月費，買的是「不用自己維護伺服器」。

    這一類我沒有放在雲端的案例。我需要長時間跑的東西，例如 2026 年 9 月初花東參訪期間每小時自動整理語音筆記，是在家裡的 Mac 上跑排程，也就是前面表格的第一條路。它的代價我實際遇過：第一版用系統排程啟動，排程程式沒有讀取語音備忘錄的權限，連續十輪失敗，當下沒有人發現。

    後端幾秒內做完的網頁：再問是用什麼寫的

    終點五：用 Next.js 這類全端框架寫的，放 Vercel

    全端框架是把畫面和後端寫在同一個專案裡，最常見的是 Next.js。判斷方法：你在電腦上只要開一個終端機視窗、打一行指令，整個網站就能動，通常就是全端專案。

    Next.js 是 Vercel 這家公司開發的，放 Vercel 支援度最好，這也是 Gary Chen 影片給的建議。如果你用的是 Next.js 以外的全端框架，先請 AI 查這個框架官方支援部署到哪些平台，再回來選。

    我的案例：知識官網。它放在 Vercel，但不是用 Next.js 寫的，是靜態頁面加上幾支伺服器端小程式（站內 AI 客服、瀏覽次數統計）。

    Next.js 專案如果有要跑很久的任務，走回上一題，選「要長時間跑或一直開著」。

    Vercel 免費方案限非商業用途Vercel 免費方案（Hobby）的條款寫明只限非商業的個人用途（2026-09-08 查官方頁）。官網、付費客戶的交付頁、課程報名頁都算商業用途，要用 Vercel 就要考慮付費的 Pro 方案，或改放其他平台。我盤點 37 個站的時候才把這件事攤開來看，官網該不該搬、要不要升級付費方案，到現在還是待決定的事。
    三家的額度與商用條款原文，我另外整理過
    • 網站放 GitHub、Vercel 還是 Cloudflare？三家免費額度、商用限制與功能差異　這一段只提 Vercel 的商用限制，那篇逐條列三家的額度、超額單價與條款原文。

    一般網頁加一小段伺服器程式：最後問要不要被外部服務叫醒或定時跑

    大部分用 AI 做出來的網頁，是 HTML 加上一小段處理密碼、存資料的程式。這一類我全部放在 Cloudflare，最後只差一題：它是等訪客來按，還是要被 LINE 這類外部服務叫醒、或定時自己跑。

    終點三：等訪客來按的，放 Cloudflare Pages 加 Pages Functions

    Pages Functions 是掛在 Pages 網站上的一小段伺服器端程式。要存資料就再接 D1（表格資料庫）、R2（放大檔案）或 KV（放小段設定）。

    我的網站後端在做什麼另外接了
    個人工作台加一道密碼，筆電手機都能看無
    合作單位的課程站站長、主講師、助教、學員四層會員KV
    調香工作坊的香氛卡站學員填配方生成香氛卡，老師後台匯出KV
    參訪行程頁成員用手機傳照片D1、R2
    學員生圖工作站密碼進場、生圖、發表到成果牆D1、R2

    Pages Functions 的呼叫次數跟靜態檔案分開算，它吃的是 Workers 的免費額度。另外，Cloudflare 官方文件現在建議新專案從 Workers 開始，Workers 也能放靜態網站，Pages 沒有停用（2026-09-15 查證）。我上面這幾個都還在 Pages 上正常運作；你要開新專案，可以直接照官方建議用 Workers。

    終點四：要被外部服務叫醒、或定時自己跑的，放 Cloudflare Workers 加排程

    我的案例：萊卡 LINE 群助理。LINE 群有新訊息，LINE 會主動通知一個網址，接這通通知的是 Workers 上的一小段程式，它把訊息記進 D1 資料庫。身上還掛著排程，每五分鐘醒來一次，把群裡的照片備份到 Google 雲端硬碟。家裡不用有任何一台電腦開著。

    六種網頁對應的平台與我的案例一覽

    終點你的網頁平台我的案例
    一公開的純靜態網頁Cloudflare Pages（GitHub Pages、Vercel 也可）攝影網站搬家、AI 名片（GitHub Pages）
    二只給特定人看的純靜態網頁Cloudflare Pages 加不收錄設定文章草稿預覽站、網站分配決策頁
    三有密碼、會員、存資料，等訪客來按Cloudflare Pages 加 Pages Functions工作台、課程站、香氛卡站、行程頁、生圖工作站
    四要被外部服務叫醒或定時跑Cloudflare Workers 加排程萊卡 LINE 群助理

    六要長時間跑或 24 小時一直開著Railway、Render 這類常駐主機雲端沒有案例，我放在家裡的 Mac

    網頁放上平台之後，我踩過的兩個坑

    部署顯示成功，網站按了卻沒反應

    密碼、API 金鑰不能跟著程式碼一起上傳，要另外在平台後台設定。我在 Cloudflare Pages Functions 上遇過：金鑰分成正式網站和預覽網站兩套，只設了一套，預覽網站就一直顯示「密碼不對」；設完還要重新部署一次才生效。部署紀錄是綠燈，不代表網站會動，要自己點一遍。

    免費額度是整個帳號共用一份

    兩家的免費方案，額度都是整個帳號加總計算，不是一個網站一份。2026 年 9 月 6、7 日，我同一個 Cloudflare 帳號裡一支每幾分鐘就跑一次的檢查程式，把資料庫的每日讀取額度吃完，同帳號其他網站的寫入也一起被擋。後來補上索引解決。所以規劃的時候，實驗性質、會頻繁自動執行的東西，要想清楚跟正式網站放不放在同一個帳號。

    判斷不出網頁是哪一種，把這段提示詞交給 AI

    把下面這段貼給幫你寫程式的 AI，它會看你的專案回答四個問題：

    請看這個專案，依序回答四個問題，每題附上你從哪個檔案判斷的：
1. 需不需要後端？（登入、存資料、藏 API 金鑰、接外部通知或排程，任一項就算需要）
2. 如果不需要後端：這個網頁要公開，還是只給拿到網址的人看？
3. 如果需要後端：後端的每個動作是幾秒內做完，還是要長時間一直開著？
4. 如果幾秒內做完：這是 Next.js 這類全端框架，還是一般網頁加一小段伺服器程式？如果是後者，需不需要被外部服務呼叫或定時執行？
最後告訴我，依照這四個答案應該放 Cloudflare Pages、Cloudflare Workers、Vercel，還是常駐主機平台。不確定的地方直接說不確定，不要猜。

    這篇的數字與判斷問題從哪來

    Cloudflare 靜態流量不計量、單檔 25 MiB、每站 20,000 檔、官方建議新專案從 Workers 開始，查證日期 2026-09-15；Vercel 免費方案限非商業用途，查證日期 2026-09-08。三個判斷問題的骨架參考自 Gary Chen〈給非技術人員的部署教學，Vibe Coding 上線前必看〉。案例來自我 2026 年 8 月到 9 月的工作紀錄。平台方案隨時可能調整，開通之前點進官方定價頁看當天的值。

    先讓手上那一頁有網址，其他之後再說

    你的網頁如果走到終點一或終點二，今天就放得上去。等網頁真的需要密碼、存資料，再往下走。我每個月固定辦兩場免費線上講座，分享 AI 應用與知識管理的實戰做法。
