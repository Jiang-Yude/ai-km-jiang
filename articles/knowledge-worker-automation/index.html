AI 工作流 / 知識工作者

都 Agent 時代了，還要學 n8n 或設計自動化小程式嗎？

知識工作者的分工法：把工作拆成卡片，每次做法都一樣的交給程式，要判斷的才交給 Agent。核心是提煉知識、架構知識的能力。

這篇在講什麼

我是知識工作者，工作大多是讀文件、做研究、分析、推理。這些事要動腦，像 n8n（把不同 App 串起來、讓流程自己跑的自動化工具）擅長的收信觸發、搬資料、定時通知，在我的工作裡比較少。但哪怕是知識工作者，還是有些東西每次做法都一樣，可以重複去處理，像我常講的 PDF 清理。這些流程讓程式處理比較好，要判斷的才交給 AI。這篇先講我的例子，再講其他人怎麼分：最近一支影片在討論「有了 AI Agent，Notion 跟 n8n 是不是可以丟了」，它引用了 Anthropic 的〈Building Effective Agents〉，分法也是同一個方向。最後講我認為背後真正的核心：提煉知識、架構知識的能力。

適合誰
  • 工作大多是文件、研究、分析，覺得自動化跟自己沒什麼關係的人
  • 看到「XX 已經被 AI Agent 取代」，不確定以前學的工具還要不要用的人
  • 想幫客戶或團隊判斷哪段工作該交給 AI、哪段該交給程式的人
你可以帶走什麼
  • Anthropic 怎麼分「固定工作流」跟「Agent」（AI Agent＝像 Claude Code、Codex 這種能動手幫你做事的 AI）
  • 除了 n8n，知識工作者還有兩種自動化做法
  • 兩個例子：我的 PDF 清理流程圖，以及 PDF 清理、圖片轉文字兩段可以直接複製的提示詞
  • 其他人也這樣分：Notion、n8n、AI Agent 怎麼分工

我的工作大多要判斷，但有些流程每次都一樣

我是知識工作者。每天大部分的工作是讀文件、做研究、分析、推理。這些事要有腦袋才做得完。

收信觸發、把資料搬到另一個地方、定時發通知，這類 n8n 擅長的固定流程，在我的工作裡比較少。所以如果只用「有沒有用 n8n」來看，我好像沒什麼自動化。

但哪怕是知識工作者，工作裡還是有一些東西，每次做法都一樣，可以重複去處理。這些流程讓程式處理比較好：程式每次照同樣的步驟跑，比每次都叫 AI 重想一遍穩定，也省錢。要判斷的，才交給 AI。

下面兩個是我自己的例子。

例子一：PDF 清理，我的流程長這樣

這是我常講的例子。

PDF 是印刷格式，是設計給人看的，不是設計給 AI 看的。我們看到的漂亮排版，背後都是規格：每一個字多大、什麼字型、放在哪個座標。一條分隔線，我們看到就是一條線，PDF 要描述的是「它的原點在哪裡、從哪裡畫到哪裡」。

表格更麻煩。框線、位置、大小全部都要寫清楚，直接丟給 AI，它讀到的常常是大量的亂碼。AI 還要再去對座標，同樣座標的才當成同一列；座標對不起來，就可能被判斷成下一列。

所以 PDF 要先做資料清理：去掉多餘的排版規格與亂碼，只保留純文字，內容才能更好地被 AI 處理。概念就是：盒子越簡單，干擾就越少。

規則只有一條：AI 不直接讀原始 PDF

我把這段做成固定的流程。腳本先把 PDF 清成純文字，AI 只讀清好的那份。判斷類型、抽文字、用 OCR 把掃描頁掃成文字，每次做法都一樣，交給程式；翻譯、分析，才交給 AI。

圖比手機螢幕寬，可以左右滑動。

文字版：腳本判斷每頁有沒有文字層 → 文字頁由腳本抽出純文字，掃描頁用 OCR 掃成文字 → 合成一份「檔名_純文字.md」→ 你選 A 純轉檔或 B 翻譯卡片化 → AI 才做研究、分析、推理。

腳本跑完會先回報，例如「這份 PDF 共 N 頁，其中 X 頁有文字層，Y 頁是掃描版」，再問我下一步。三種類型的分工是這樣：

類型怎麼判斷腳本做什麼AI 做什麼
文字型有文字層抽文字，圖片另存只讀純文字檔
掃描型沒有文字層，全是圖片每頁抽成圖片，用 OCR 掃成文字只讀 OCR 掃出來的文字；OCR 掃不好的頁，才用圖片辨識讀那一頁
混合型部分頁有文字層，部分頁是掃描有文字的頁抽文字，掃描頁用 OCR 掃成文字只讀合起來的純文字檔

每一段用不同等級的模型

拆開之後還有一個好處：每一段可以用不同等級的模型，省成本。

這一段建議模型原因
叫腳本跑、整理成 Markdown（不翻譯）Haiku只是照步驟叫程式，不需要語言理解
翻譯、表格結構與複雜排版Sonnet要理解語言和版面，不需要頂級推理
標籤統整、多份文件交叉分析Opus要跨文件比對與分類判斷

不想分那麼細，用 Sonnet 跑完全部流程，基本上也都能處理。

翻譯和卡片化，為什麼要各自獨立

翻譯獨立一個階段，是為了避免上下文爆炸。長文件在同一個視窗一路翻到底，翻到後面每一段都要把前面重讀一遍，越來越慢，甚至直接撞到長度上限。同一個術語前面翻「新創公司」、後面翻成「創業企業」也很常見。所以要分章翻，搭配一份字典檔和翻譯規範，用語才會統一。

卡片化，是為了讓 AI 每次只處理一小塊。丟越多東西給 AI，它就越渙散，跟人一樣。與其把一整本書塞進一個檔案，不如一章拆成一張卡片。每張卡片可以單獨搜尋、連結、引用，需要的時候再像積木一樣組合起來。

直接用：PDF 清理的提示詞

把這段貼給 Claude Code、Codex 這類能動手的 AI，它會先寫好清理的小程式再跑。程式留著，下一份 PDF 直接叫它用同一支：

請幫我把這份 PDF 轉成 Markdown，照這個順序做： 1. 不要直接讀 PDF。先寫一支 Python 小程式（可以用 PyMuPDF）前處理，判斷每一頁有沒有文字層 2. 跑完先告訴我：共幾頁、幾頁有文字層、幾頁是掃描版 3. 有文字層的頁：抽出純文字，存成「檔名_純文字.md」，表格盡量轉成 Markdown 表格（轉不好的保留原樣並標註），圖片另存 4. 掃描版的頁：每頁抽成圖片，先用 OCR 程式掃成文字（辨識語言設成這份文件的語言），補進同一份純文字檔；OCR 掃出來有問題的頁（例如一堆亂碼、整段空白），再用你的圖片辨識讀那一頁 5. 做完先停，問我下一步：A 純轉檔（保留原文），還是 B 翻譯成繁體中文並拆成卡片 6. 之後只讀「檔名_純文字.md」，不要再回頭讀原始 PDF 7. 把這支小程式存起來，下次有 PDF 就直接用它 PDF 檔案：[放上你的 PDF]

例子二：圖片要轉文字，直接叫光學辨識（OCR）

掃描的 PDF、截圖、拍照的文件，要轉成文字，直接叫光學辨識（OCR，Optical Character Recognition）就好。

順序是：先用 OCR 把圖上的字掃成文字，再讓 AI 讀取。掃成文字這一段每次做法都一樣，交給 OCR 程式；掃出來的文字要怎麼整理、怎麼分析，才交給 AI。

OCR 掃出來有問題的頁，才讓 AI 用圖片辨識去讀那一頁。

這段提示詞可以直接複製：

請幫我把這些圖片轉成文字，照這個順序做： 1. 先用 OCR（光學辨識）程式把每張圖上的字掃成文字（辨識語言設成圖上的語言），存成「檔名_純文字.md」，不要自己看圖猜字 2. 盡量保留原本的標題、段落、表格與數字 3. 掃不清楚的地方不要猜，在那個位置標註「原圖局部小字未辨識」 4. OCR 掃出來有問題的頁（例如一堆亂碼、整段空白），再用你的圖片辨識讀那一頁，補進同一份文字檔 5. 掃完之後，只讀這份文字檔，再幫我整理重點 圖片：[放上你的圖]
要注意版面複雜、手寫字、畫質差的圖，辨識出來會有錯字，重要的內容還是要校對一次。

不只我這樣分：AI Agent 不是來取代 n8n 的

最近看到一支影片在討論：有了 AI Agent，Notion 跟 n8n 是不是可以丟了？都 Agent 時代了，還要學 n8n、還要設計自動化小程式嗎？影片的答案，跟我的做法是同一個方向。

新工具不一定是來取代舊工具的。有一種關係是新的能把舊的整個換掉，像 Uber 跟計程車行、Notion 跟 Evernote。AI Agent 跟 Notion、n8n 不是這種關係。Claude Code 技術上也能做出一個資料庫 App，但每改一個欄位、換一個版面，都要跟 AI 來回講一輪；團隊、外包、學員也不可能每個人都開一個 Claude Code 來查資料。

三個工具各站一個位置。可以這樣分：

工具負責什麼例子
Notion團隊協作的管理中心，也是讓 AI Agent 互相協作的中台要分享出去的文件、給外包的 SOP、不用寫程式的內部管理介面
n8n不需要 AI 判斷的固定流程收到信就觸發、搬資料、定時發通知
AI Agent需要推理的任務篩新聞、分析信件該怎麼回、把逐字稿整理成文章

有了 AI，是叫 AI 幫忙改 n8n。以前要自己研究每個節點怎麼設定，現在跟 AI 說「幫我改這條工作流，加一個條件判斷」，它就能把設定產出來。n8n 還是執行引擎，AI 讓你開得更快。

以前學的沒有白學。累積過 Notion 的資料庫思維、n8n 自動化設計能力，進到 AI Agent 時代反而上手更快，因為你已經知道自己的流程長什麼樣子。沒搞懂流程就直接跳到 AI Agent，很容易變成盲目的自動化。

所以標題那一題的答案是：還是要學。這些工具可以交給 AI 幫你開，但流程要你自己懂。

影片也是引用別人：Anthropic 怎麼分固定工作流和 Agent

這個分法也不是影片自己發明的，它引用了 Anthropic 的文章。2024 年底，Anthropic 發表了一篇教人怎麼做 Agent 的文章〈Building Effective Agents〉。它把用 AI 做事的系統分成兩種做法，大意是這樣：

適合的任務特性
固定工作流定義清楚的任務比較可預期、穩定
Agent需要彈性、要讓 AI 自己做決定的任務彈性大，但不一定穩

文章也提醒兩件事：這類讓 AI 多步驟做事的系統，通常是拿速度和成本去換更好的表現；所以先找最簡單的做法，很多事問 AI 一次就夠，需要的時候才增加複雜度。

這個分法我同意。不用判斷的事，交給固定流程跑，比每次都叫 AI 重想一遍穩定，也省錢。

知識工作者的三種自動化做法：n8n、小程式、讓 Agent 調程式

把我的例子和其他人的分法放在一起，知識工作者的自動化可以分成三種：

做法怎麼運作適合
固定工作流（像 n8n）把不同 App 串起來，觸發後照固定步驟跑收信、搬資料、定時通知這類跨 App 的固定流程
自己寫小程式把每次做法都一樣的那一段寫成程式檔案處理、格式轉換、檢查這類固定動作
叫 Agent 去調動已經寫好的程式Agent 負責判斷什麼時候要用、要處理哪些檔案，實際處理交給程式判斷和固定動作混在一起的工作

對我這種工作大多要判斷的知識工作者，第三種特別好用，前面的 PDF 清理就是這一種。判斷的過程中，常常有一段是固定的。那一段寫成程式，讓 Agent 在需要的時候去叫它。

程式也不用自己從頭寫，可以請 AI 寫。先讓 AI 把流程跑通，再把固定的那一段請它寫成程式。

怎麼找出可以自動化的那一段：先把工作拆成卡片

要找出哪一段可以自動化，要先把工作拆開。

我之前講過，Obsidian 把知識拆成筆記卡片，Trello 把任務拆成待辦卡片，n8n 把流程拆成節點卡片。它們表面上看起來完全不同，核心都在做同一件事：卡片化。

工作也一樣。一份研究分析的工作拆成一張一張卡片之後，就看得出來：

  • 哪幾張每次做法都一樣：寫成小程式，或交給固定工作流
  • 哪幾張每次都要判斷：交給 Agent，或自己來

沒拆開的時候，整份工作看起來都要動腦，所以會覺得「我的工作沒辦法自動化」。

延伸閱讀
  • 讓 AI 只做需要判斷的事，其他交給程式：這篇把「要判斷」到「完全不變」再細分成四種情境，附一個可以點選的決策樹。

核心是提煉知識、架構知識的能力

影片裡把這件事叫做「個體架構力」：先反推自己的工作流程跟需求，再量身打造一套自己的管理方式。

用我的話講核心就是提煉知識、架構知識的能力。

工具會一直換。我之前也講過，會用 ChatGPT、會用自動化工具、會用 AI 寫程式，是不同領域的應用方式，不存在高低之分。真正會留下來的，是你能不能把自己的工作拆開、看出每一段是什麼，再決定每一段交給誰。

當你掌握這個思維，任何新工具到你手上，都能快速上手、為你所用。

今天可以做的第一步：把一份工作丟給 AI 拆卡片

挑一份你最常做、最花時間的工作，把流程貼給 AI，請它幫你拆。提示詞寫好了，複製貼上就能用：

我有一個工作需要整理，請幫我： 1. 拆成最小步驟，每一步只做一件事 2. 每一步標註：每次做法都一樣（可以寫成小程式或固定工作流），還是每次都要判斷（交給 AI Agent 或我自己） 3. 標出哪幾步最花我時間 工作內容如下： [貼上你的工作流程]

拆完之後，先從「每次做法都一樣、又最花時間」的那一步開始。請 AI 把那一步寫成小程式，以後叫 Agent 去調動它。
