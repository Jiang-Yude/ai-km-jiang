From Chatbox to Agent / Field Notes

你以為在做一個成品，
其實在養十個半成品

發佈 2026-06-26 ｜ 最後更新 2026-06-26

我最近看到一支訪談短片，把一個人從網頁版 AI 聊天，一路用到多模型協同跟 Agent 的心態，講得專業、好笑、又好懂。它把 Agent 的可能性說清楚了，也把隱憂講清楚了。這篇文章是我的推薦與延伸，最後附上我自己用 AI 顧問做專案收斂的真實做法。

發布：2026-06-26更新：2026-06-26

這支影片叫《我只是想做個小網頁，後來被 Codex 徹底帶偏了》，出自 YouTube 頻道「灵姐说AI（Ling Talk AI）」。它用一個訪談的形式，請一位把 AI 越用越深的人，回顧自己從聊天到 Agent 的整段路。表面是搞笑，底層其實很準。

我會想把它整理成一篇文章，是因為它替很多人說出了還沒講清楚的感覺。如果你還停在網頁版 AI 聊天，它可以讓你先看見 Agent 的可能性長什麼樣子。如果你已經想試 vibe coding，或剛開始用 Agent，它會先幫你把後面的坑攤開來看。

For You 網頁版 AI 使用者

還停在開網頁、丟問題、看回答的階段。這支片會讓你看到，AI 從聊天升級到動手做事，是怎麼一步一步發生的。

For You 想試 vibe coding 的人

還在猶豫要不要讓 AI 幫你寫東西、做工具。它把那種一開就停不下來的感覺講得很誠實。

For You 剛開始用 Agent 的人

已經在用 Claude Code、Codex 這類會動手的工具。它講的隱憂，正好是你接下來會遇到的關卡。

影片在講什麼：一條從聊天到 Agent 的路線

影片用「越用越上頭」當比喻，把每一個 AI 工具當成不同強度的東西。我把它的主線整理成六個階段，每一段都附上影片回跳連結，你可以點進去聽原汁原味的講法。以下是轉述摘要，完整內容請看原片。

影片自己的定調它在說明欄寫得很清楚：這不是嚴肅醫學建議，也不是工具評測，是一條認真胡說八道的 AI 黑色幽默短劇。畫面裡受訪者掛著「L 姐，重度 Codex Coding 上癮者」的字卡，背景牆上寫著「珍愛生命，遠離 Vibe Coding，謹慎使用 AI 工具」，整支片就用這種公益宣導的反差在說故事。

第一階段：網頁版聊天，輕鬆無壓力

一開始就是大家一起玩。先用豆包聊聊天、生生圖，開心一下。再試千問，中文還行、比較穩定，像常備口糧。這個階段的 AI 很輕，沒什麼危險，也談不上上癮。（影片 00:07 起）

第二階段：開始管不住手

碰到 Deepseek 之後感覺不一樣，有邏輯、有分析，又便宜。於是開一個對話、再開一個對話，問完一個問題又覺得不夠，再新建一個，像嗑瓜子一樣停不下來。（影片 00:36 起）

第三階段：工具型轉折，AI 開始真的幹活

上了 GPT 之後感覺變了。你把想法丟給它，它會直接動手：你說要做工具，它幫你拆需求；你說要寫腳本，它直接給方案；你說要做頁面，它連結構、程式碼、互動都想好了。影片裡有一句很有意思的自嘲：以前還安慰自己動手有價值、過程很重要，後來發現過程也可以外包。（影片 01:06 起）

第四階段：多模型協同，像雇了一個團隊

接著是 Gemini，上下文很大，一堆文件、網頁、影片、圖片丟進去都能吞，而且做出來的東西審美還在線，拿出去別人會說有點水平。（影片 02:15 起）然後是一直忍著沒碰的 Claude 跟 Claude Code。第一次用就有點恍惚，它不只是回答問題，是在理解你想做什麼，需求講不清楚它會反問你，文件結構亂它能幫你理順，從架構、邏輯、程式碼到修 bug，甚至哪裡可以優化都能接。影片的形容是：你會有一種錯覺，覺得自己像雇了一個不會睡覺的團隊，早就不只是在用一個工具。（影片 02:52 起）

第五階段：行為翻轉，需求開始自己長大

這裡是整支片最關鍵的觀察。以前是有問題才打開 AI，現在是打開 AI 才有問題。（影片 04:07 起）本來只想做個小網頁，做完想加登入，加完想加後台，有了後台想加資料庫，有了資料庫想做成 SaaS，做成 SaaS 想接金流，接完金流又想發給用戶試試。影片點得很準：AI 不會攔你，它只會說「可以的，我們一步一步來」。

影片金句我不缺工具，我缺的是克制。（影片 05:47 起）

第六階段：四線全開，加上 Codex 徹底亂了

到後面是四條模型線一起跑：Deepseek 負責便宜大碗的雜活，GPT 負責主力推進，Gemini 負責吞資料跟審美，Claude 負責架構跟 coding，最後 Codex 一上就全亂了。每一個冒出來的點子都覺得應該被做成專案，半夜刷到 GitHub 專案就想複刻，看到別人做 AI 畫布、自動剪輯、MCP 都想做。電腦裡面堆的，都是一個又一個沒收尾的現場。（影片 04:53 起）

影片把隱憂也講清楚了

很多介紹 AI 工具的內容只講好處。這支片難得的地方，是把代價也說了出來，而且說得很具體。

它的核心反省那時候的自己以為在提高效率，其實在擴大自己慾望的頻寬。以前不會做，所以不想做；現在 AI 說你都可以做，於是白天有十個想法，晚上 AI 幫你完成八個，第二天就冒出三十個想法。（影片 06:52 起）
影片的提醒你會以為自己變高效了，其實是被高效反噬。（影片 07:21 起）

然後就是你提到的那句，也是我覺得整支片最值得停下來想的一句話：

影片金句你以為你在做一個成品，
其實你在養十個半成品。
（影片 07:56 起）

影片最後的態度也很真實，它沒有假裝可以瀟灑戒掉。被問到戒掉了嗎，回答是戒掉是不可能了，現在只是盡量把它 agent 化。還補了一句提醒：vibe coding 要謹慎，你以為打開的是一個 demo，實際上打開的是另一個人生分支。（影片 08:32 起）

我的延伸：工具不是問題，收斂才是功課

這支片我看完最大的共鳴，是那句養十個半成品。因為我前幾天也剛好遇到一模一樣的事，只是我多做了一個動作：讓 AI 顧問幫我做收斂。

我用我做的「活的馬斯克技能包」檢視自己手上的專案，把每一個都攤給它看，請它用第一性原理幫我判斷。它給我的回應很直接：

AI 顧問對我說我以為我在開發八個產品，但實際依照目前情況分析，只有三個有商業價值。

這句話跟影片那句養十個半成品，講的其實是同一件事的兩面。影片講的是慾望怎麼被工具放大，我這邊補的是：放大之後，你需要一個會幫你收斂的機制。工具讓你什麼都做得出來，但什麼值得做、什麼該先停，這個判斷不會自己長出來。

沒有收斂機制 養十個半成品

每個想法都開一個專案，每個專案都做到一半。資料夾越開越多，token 越燒越快，最後分不清自己是在創作，還是在當一堆半成品的管理員。

有收斂機制 先篩，再做三個

把想法先丟給 AI 顧問做第一性原理拆解，問清楚哪些有真實需求、哪些只是自己想做。砍掉沒商業價值的，把力氣集中在會留下來的少數幾個。

我自己的做法，分享給你參考

如果你也常有「什麼都想做」的狀態，可以試試這個順序。它不需要你會寫程式，只需要你願意在動手前先停一下。

  • 把手上所有想做的專案列出來，一個都不要漏，先承認自己貪心。
  • 丟給一個 AI 顧問，請它用第一性原理逐一反問：這個的真實需求是什麼？使用者現在用什麼替代方案？我解的是需求，還是只是想做？
  • 請它幫你排出哪些有商業價值、哪些只是練習、哪些可以直接放掉。
  • 只留下會被你累積下來的少數幾個，其他先記著、不開工。
  • 把省下來的力氣，花在把這幾個做完、做好，讓它真的變成你的資產。
我的結論AI 讓速度變便宜了，所以速度不再是差異。真正會留下來的，是你的判斷力，還有你一個一個做完、累積起來的東西。影片講的是怎麼被工具帶著跑，我想補的是：你也可以反過來，用一個會反問你的 AI，把自己帶回該做的那幾件事上。
