什麼叫子代理？從分頭查資料到 30 人工作坊頁面

讓 Agent 開分身，分頭工作，最後再一起整併。兩個案例帶你看懂：怎麼用獨立研究保留矛盾，又怎麼把大量同版型任務拆成幾批完成。

發佈 2026-09-01 ｜ 最後更新 2026-09-01

這篇在講什麼

子代理就是讓 Agent 開分身，分頭進行工作，最後再一起整併。這篇用兩個我實際採用的案例說明：第一個是把官方說法、網路正面評價、網路負面評價分開搜尋；第二個是替約 30 位工作坊學員製作同版型的獨立頁面。

適合誰
  • 問 AI 某個工具好不好用，拿到的答案總是很像產品介紹。
  • 想比較多個工具，又擔心 AI 太早選邊站。
  • 手上有一批同版型、內容各自不同的重複工作。

什麼叫做子代理？

簡單來說，就是讓 Agent 開分身，分頭進行工作，最後再一起整併。

主 Agent 負責拆任務、分配工作、收回結果與最後整合。每一隻子代理只處理自己拿到的部分。只要任務可以清楚切開，就能讓多個工作同時往前走。

同一個問題，拆不同角度

讓每組獨立研究，避免先看到其他組的結論。重點是保留觀點差異與矛盾。

同一種任務，套相同模板

把固定版型與個別資料交給不同子代理。重點是分批並行、統一驗收。

案例一：不同角度並行查資料

問 AI 某個工具好不好用時，它很可能先找到官方網站、產品文件或發布文章。官方資料適合建立產品承諾的基準，實際使用經驗則要另外找。我的做法是把搜尋拆成三組，先讓它們各查各的。

第一組

官方怎麼說

  • 產品宣稱能做什麼
  • 支援平台、方案與條件
  • 限制、例外與已知問題
  • 發布日期與適用版本
第二組

網路正面評價

  • 什麼人在什麼任務覺得好用
  • 效果是省時、易用或品質穩定
  • 使用版本、方案與裝置
  • 成立所需的使用前提
第三組

網路負面評價

  • 失敗發生在哪個步驟
  • 功能、價格、穩定或期待落差
  • 是單一案例或重複出現
  • 新版是否已修正
先搜尋，再分析每組第一階段只列來源與原文摘錄。三組都交回後，才比較日期、版本、方案、地區與使用情境。

可以直接複製的提示詞

查某某主題，分三次獨立搜，不要合併
1 官方怎麼說
2 網路正面評價
3 網路負面評價
每一組只列來源與原文摘錄，先不要分析
三組都給我之後我們再一起看

沒有來源不准下結論
來源互相矛盾的時候要明說矛盾在哪
不准硬整合成一個好聽的版本

三組資料回來後，先查五件事

  1. 日期是否不同，舊評價談的問題是否已在新版改變。
  2. 免費版、付費版、企業版是否使用不同功能。
  3. 地區、價格、法規與開放範圍是否不同。
  4. 雙方原本要完成的任務是否相同。
  5. 證據是可重現紀錄、完整案例，還是單句感想。
保留未決狀態無法判定哪一方較可靠時，明確寫出還缺什麼資料，不把矛盾磨成一句順耳的總結。

三組角度也可以替換成技術面、商業面、法規面；競品 A、B、C；或短期、中期、長期。結構維持一致：各組獨立、每項有來源、矛盾明確保留。

案例二：同一份模板，並行製作 30 位學員頁面

我有一個約 30 人的工作坊。成果發表需要一個總頁，另外每位學員都有自己的獨立頁面。每個人的內容不同，頁面模板相同，這類任務很適合分批並行。

做出來的成果頁在這裡：數位起步走 學員作品集 ↗。八組、29 位學員，每個人都有自己的頁面，總頁負責分組導覽、投票與留言。

第 3 批學員 21 到 30

以每批 10 頁為例，30 位學員可以拆成 3 批。實際每批放幾頁，會依當時使用的工具、任務複雜度與可用資源調整。

STEP 1先定共用模板

欄位、版型、導覽與檔名一次定清楚。

STEP 2資料逐人分開

姓名、作業內容與素材只放進自己的資料包。

STEP 3分批派工

每隻子代理只處理指定名單，不自行換模板。

STEP 4主 Agent 整併

收回頁面，接上總頁、導覽與相互連結。

STEP 5Claude Code 全局審稿

檢查版型一致、內容未混用、必要欄位未漏。

工作坊頁面分批派工提示詞

你是工作坊學員頁面的製作子代理。

本批負責學員：[貼上本批名單]
共用頁面模板：[貼上模板或提供檔案位置]
個別學員資料：[逐位貼上姓名、作業內容與素材]

請依同一份模板，分別完成每位學員的獨立頁面。

共同規則：
1. 版型、欄位順序與導覽結構不可自行更動。
2. 每位學員只使用自己的資料，不混用其他人的內容。
3. 原始資料沒有的內容不要補寫，缺少欄位標示「未取得」。
4. 每完成一頁，回報學員姓名、頁面檔名與缺少資料。
5. 這一批全部完成後，再交回主 Agent 整併。

限制：上下文不會自動跟著走

彼此不干擾會帶來上下文缺失。子代理只知道派工時收到的內容。主 Agent 知道的背景、使用者剛補充的要求、另一批發現的問題，不一定會自動出現在每隻子代理的任務裡。

每隻子代理都要拿到的五項脈絡

  1. 任務目標：這一批要完成什麼。
  2. 必要脈絡：讀者、用途與前後關係。
  3. 共用模板：版型、欄位與輸出格式。
  4. 個別資料：這隻子代理真正要處理的內容。
  5. 禁止事項與驗收條件：哪些地方不能改，完成後要檢查什麼。
優點一：分頭並行

原本依序完成的工作，可以改成幾批同時進行。

優點二：獨立運作

每組沿著自己的範圍完成工作，不先被其他組的結論帶走。

主 Agent 最後仍要負責整併與全局檢查。工作坊頁面還會再請 Claude Code 審稿，確認所有頁面套用同一規格、內容沒有混用，也沒有漏掉必要欄位。

三組查完，先問這七題

  1. 每個重要說法都有可點來源嗎？
  2. 原文摘錄真的支持旁邊那句話嗎？
  3. 日期、版本、方案與地區有寫嗎？
  4. 正面與負面評價都有具體使用情境嗎？
  5. 同一篇內容是否被轉載多次，卻被算成多個獨立來源？
  6. 矛盾有被逐條列出，還是被一句總結帶過？
  7. 哪些地方仍未取得資料，需要實測或再查？

先把資料分開查，再把矛盾攤開看。沒有來源不下結論，無法確認就保留未決。

分頭搜尋可以增加觀點覆蓋，也讓矛盾有地方被保留下來。它無法保證結果一定正確。三組仍可能看到相似的搜尋排序，網路評價可能缺少上下文，官方資料也可能沒有寫出真實使用時的摩擦。所以「有來源」只是第一道門檻，下一步仍要確認來源是否支持那句話，以及資料是否仍在有效期內。
