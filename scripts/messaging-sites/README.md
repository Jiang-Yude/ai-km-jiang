# 對外講法漂移健檢：多站設定

檢查一個網站的「對外自我介紹」有沒有跟真相脫節。

## 為什麼有這東西

2026-08-25 官網的 AI 導覽還在推「免費安裝 AI 辦公室」，但那東西 8/19 就改成個人陪跑的
交付內容了。漂移將近三個月沒人發現。根因是同一份接待腳本被人工抄在八個檔案裡，
改了一份，另外七份不會跟著動。

## 加一個站要做什麼

兩件事，不用改程式：

1. `sites.conf` 加一行：`<站台代號>|<站台根目錄>|<上游 repo 或 ->|<required 或 optional>|<說明>`
2. 開一個 `<站台代號>/` 資料夾，放三個設定檔

三個設定檔都是純文字，`#` 開頭是註解，空行忽略：

| 檔案 | 放什麼 | 留空會怎樣 |
|---|---|---|
| `scope.txt` | 要掃哪些檔（一行一筆，支援 glob） | 沒東西可掃 |
| `blocklist.txt` | 禁用詞（`<正規表達式>:::<為什麼禁>:::<改用什麼>`） | 不掃禁用詞 |
| `versioned.txt` | 哪些檔必須標上游 commit | 跳過版本檢查，不算失敗 |

站台根目錄不在這台機器時：標 `optional` 的 SKIP 不算失敗（排程機器不一定有每個客戶站的
clone），標 `required` 的算 FAIL（根目錄打錯會被抓出來，不會靜靜跳過）。

`scope.txt` 與 `versioned.txt` 的路徑一律相對站台根目錄，絕對路徑與 `../` 會被擋——
「限縮掃描範圍」是這套設計的核心保證，逃得出去就等於沒限縮。

## 怎麼跑

```bash
python3 scripts/messaging-check.py                    # 跑清單裡所有站
python3 scripts/messaging-check.py --site jiangyude   # 只跑一站
python3 scripts/messaging-check.py --site jiangyude --root /tmp/測試副本   # 換根目錄測
```

exit code 三態：

| code | 意思 |
|---|---|
| 0 | 全部檢查都跑完，而且通過 |
| 1 | 發現漂移，或設定本身有錯 |
| 2 | 有檢查沒跑完（GitHub API 連不上、必要站不在這台機器），沒發現漂移但不算綠 |

也被 `scripts/daily-health-check.sh` 當第 5 項呼叫，那邊同樣分三態，exit 2 不印「全綠」。

## 兩個設計取捨（照抄前先讀）

**掃描範圍一定要限縮。** 同一句話換個地方意思完全不同：「第一個 AI 員工」在
`articles/` 底下是文章主題，完全合法；只有在接待腳本那幾個檔裡才是違規。掃全站會大量
誤報，誤報多了就沒人看，機制等於沒有。

**抓不到上游算「沒跑完」，不算通過也不算失敗。** GitHub API 沒網路或額度用完時走 exit 2。
排程機器的網路狀況不該把整份巡檢弄紅，但也不能反過來印「全綠」——那叫假全綠，
是 2026-08-26 Codex 跨家審抓到的第一個洞。真的版本對不上才算 FAIL。

**中文站也要寫英文規則。** 掃描範圍如果含 `en/` 的檔，禁用詞清單只寫中文等於英文那半
完全沒掃。這是同一次跨家審抓到的第二個洞，實際漏掉了 `en/index.html` 裡的
`first AI employee`。

## 這個機制擋不住什麼

只擋得住「用了禁用詞」，擋不住「換句話說但意思一樣」。語意層那半靠月度知識庫健檢
第 5 路探子第 ⑩ 項的人工判斷，兩邊是配套，不能只留一邊。
